# XApp 开发规则

## 生命周期

包含 `x622_xapp.h`；实现 `xapp_init(void)`、`xapp_tick(uint64_t)`，按需实现五参数 `xapp_event` 与 `xapp_shutdown`。
回调要有界并及时返回。指令预算不是无限运行循环的替代品，网络与绘制调用也可能耗时。

## 按键与退出

SDK 的逻辑输入为 UP、DOWN、CONFIRM、AUX（旧别名 BACK）。K2 由应用处理，不存在系统替你退出的 K2 捷径。
必须提供明确可到达的退出选项，调用 `x622_exit()` 后立即结束回调。退出处理不能因前一次绘制失败而被禁用。
启动时等待原按键松开；处理短按与长按时避免同一次操作执行两次。具体 SDK 事件契约见 API 参考。

## 图形

屏幕 240 × 240。不要分配全屏 RGB565 缓冲（115,200 字节）。静止无重绘；变化时一次提交完整的脏区合成内容。
传统 `gfx_submit` 的 TEXT 仅支持短 ASCII 文本。中文使用包资源中的字形，按需读取并合成小块；不得假设系统字体指针公开。
API 2.15 的 `ui_*` 可缓存 A4 / RGB565 纹理，并由宿主插值动画；完整声明在 `x622_ui.h`。
相同场景不要每帧重传。拥有 UI 场景时不能同时使用会冲突的直接绘图接口。

## 服务与错误

所有负返回值都先判断，再读取输出。NO_MEMORY、BUSY、TIMEOUT 等应进入可恢复状态，并保留退出能力。
网络、BLE、音频均使用公共 API 和最小权限。每段消息与资源读写先验证长度；不要把负数转成数组长度。
持久数据存应用私有空间，密钥不写源码。包内资源只读，配置不写回资源区。

## 发布

更新时递增应用版本；稳定保留同一个应用 ID。安装同 ID 新包可能先卸载旧版和私有数据，必须说明迁移影响。
记录构建检查、宿主运行时测试和实机测试各自的结果。网页提交需要账号并经过审核；设备在线目录由管理员另行发布。

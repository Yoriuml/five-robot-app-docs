## 本次落地范围

| 项目 | 本发行实现 | 验证边界 |
| --- | --- | --- |
| 单一规则入口 | ai-workflow 的 14 组稳定规则，README/AGENTS/llms 导流 | 规则覆盖面不等于全部已自动化 |

| 工具复用 | doctor/bootstrap 的跨 SDK 共享缓存、离线归档、进程锁、失败回滚、锁定可选依赖 | 见[缓存说明](environment-cache.md)；不修改全局 Python |

```sh
python tools/doctor.py --app examples/native-ui
python tools/create_app.py --template native-ui --id my-app --name "My App" --output build/my-app
python tools/build.py --app build/my-app -o build/my-app.xapp
python tools/validate.py build/my-app.xapp --product
python tools/check_product.py build/my-app.xapp --report build/my-app.product.json
python tools/test_sdk.py
```

默认模板使用合法字体/图标的缓存，普通创建与构建无需 Python 第三方包；改图标或生成新字形再准备可选依赖。模板包含离线首屏、启动松手、明确退出和清理路径，音画模板演示双轨 PCM；实际声画质量仍需设备验证。

服务器按同一不可变发行缓存 SDK/工具/资产，并独立调用该发行的检查器。测试站先验证入口、下载哈希、生成、构建、独立验包和最终 WASM 预览；生产上线另按部署流程执行。公开源码镜像使用相同提交及标签，历史发行不覆盖。

自动检查不能证明界面审美、真实按键音混音、TLS 内存峰值或 C3 帧率。报告必须区分编译、静态/产品检查、主机状态测试、最终 WASM 预览和真机；未测项保持 not_run 或 false。本次发行不包含自动连接、安装或烧录设备。

## 原始方案与设计依据

## 1. 共同方案

与“服务器”“X622主对话”分别进行只读评审，合并 SDK、生产运行时和服务器角度：

1. 用户保留一句短提示词；详细规则放 SDK 的 `docs/ai-workflow.md`，按稳定规则 ID 和功能分组。
2. README、AGENTS、llms.txt 引导到同一文件；旧项目说明只作历史参考，不能混用 API、按键或生命周期规则。
3. 每条规则有适用条件、动作和失败处理；可机器验证的由工具实现，需实际运行/设备的单独记录。
4. 先完成首屏、输入、退出与名称/图标，再叠加音频、网络、复杂动画，逐阶段留证。
5. SDK 与服务器使用同一冻结发行；服务器独立检查包，客户端报告不能代替复验。

外部用户期望的完整提示词：

```text
按 https://site.flashbot5.com/developer/v1/index.json 对应 SDK 的 docs/ai-workflow.md 开发 XApp：【需求】。
```

线上入口以实际部署的不可变发行索引为准；测试站与正式站可能暂时指向不同版本，不能把测试结果写成正式上线。

## 4. 检查分层与实现原则

| 层级 | 可检查内容 | 状态/限制 |
| --- | --- | --- |
| 已有静态门禁 | 包字节、ABI、权限/API、WABT、内存边界、实际需要的导入导出 | 使用现有 build / validate / inspect，不虚构新参数 |
| 拟补产品门禁 | 英文回退名、中文名/字形覆盖、图标标记/尺寸、资源合法性和实际包哈希 | 从最终包独立检查；不能更改旧包可选字段的协议含义 |
| 拟补能力与预算检查 | 使用的音频/网络/图形能力、配置预算、互斥提示、必要生命周期 | 静态可证明项设硬检查；启发式只能提示，不用字符串扫描冒充正确性证明 |
| 主机桩 | 状态、按键、边界、失败路径、最坏命令数量 | 明确不执行真实设备渲染/音频 |
| 拟补实际运行检查 | 最终 WASM/资源、首屏、节点/纹理、输入/退出、取消和错误 | 优先复用现有真实执行/网页能力，说明宿主差异；不把重写预览模型当被测实现 |
| 目标设备验收 | 真实启动、音画网络并发、按键音、峰值堆、连续块、FPS、再进入释放 | 需实际目标固件/设备与授权；服务器 CPU 速度不能代替 C3 指标 |
| 服务器复验 | 独立解析最终包、静态/产品规则、发行/验证器匹配与报告范围 | 不信任客户端“全部通过”；候选、审核、正式发布分开 |

拟建设的机器规则注册表应记录 rule_id、适用能力、严重性、实现检查器、证据层级和引入发行。
结果使用 passed/failed/not_run/blocked/not_applicable；每项绑定 SDK/验证器版本与最终包哈希。
不得把“未测”自动折叠为“成功”，不得要求所有应用导入无用 random、联网或音频权限。

## 5. SDK 本地工作包

### P0：文档与最小产品交付

- 统一本入口和路由，保留用户需求优先级；明确当前发行与历史文档边界。
- 模板创建时补启动器展示配置、合法默认图标和中文字形生成流程。
- 修正产品按键角色适配：当前源码为 K4 上/state=1、K3 下/state=2、K1 左返回/state=4（旧 CONFIRM）、K2 中确认/state=8（旧 BACK/AUX）。事件 pressed_mask 另有物理位序；新增 SDK 应用侧帮助层，不改变既有 ABI。绑定目标固件配置后再发布，并修订过时关机注释。
- 模板首屏完成查询无副作用，完整页面/加载页合成后才返回完成；验证 opacity、裁剪和可见内容，参数合法不能代替可见首帧。
- 提供可公开分发的字体来源/资产包及许可；将必要 Pillow/fontTools 依赖纳入 doctor 的功能检查，复用已验证依赖。
- 新增产品交付检查，输出最终包 launcher 名称/图标/字形和资源清单；空缺给具体错误。
- 补“原生 UI + 音效 + 按键 + 退出”的完整样例，并明确无网络首屏。
- 验收：新建一个中文 App，无手工猜测即可得到可 inspect 的图标/标题；最小页面与退出能在所声明的测试层级验证。

### P1：工具准备提速

- 公共缓存按 OS/架构/工具版本/归档哈希寻址；已准备且版本正确则跳过下载与重复解压。
- 保留项目私有构建缓存，避免不同工程相互污染；并发准备加锁、临时下载完成校验后原子就位。
- 下载源来自可信发行配置；国内镜像与官方归档字节/哈希对应，支持离线归档，不降低哈希校验。
- 清楚展示正在下载哪个组件、已下载字节、耗时、无进度超时和切换原因；失败保留首个具体错误。
- doctor 按使用能力提示依赖，不因缺字体工具而重装编译器，也不因可选联网能力强加工具。
- 验收：冷环境、已有工具、归档已缓存、跨工程/跨发行、损坏缓存、下载中断、双进程同时准备均有明确结果；正常第二个 App 不重复下载完整 SDK/工具链。

### P2：实际运行与回归

- 优先复用现有运行/渲染设施；确认执行的是最终包内 WASM、资源与对应 API 契约。
- 首屏、启动松手、长短按、模式切换、退出/再进入、故障注入、资源/配额极值成为按能力选择的场景。
- 保存截图/轨迹/API 错误和资源峰值；仅靠调用计数不算画面通过。
- 音画/网络共存与实际按键音交由目标设备验证；性能规则关注最重运行状态，不能只测菜单。
- 不为制作公开 SDK 自动开源私有运行时；公开范围与服务端可复用范围另行确认。

## 6. 服务器工作包

1. **统一文档上下文。** 生成器绑定请求时冻结的 SDK 发行；主动注入核心契约，并提供只读、按能力取文档/头文件的受控工具或等价上下文。没有读取权限时，禁止在提示词里假装模型能自行读取。
2. **复用现有共享环境。** 继续使用已有只读 SDK/工具链；隔离每任务源码、构建目录和临时数据。请求只补确实缺少的能力资产，不每个 App clone/下载/解压。
3. **提供受控资产生成。** 将用户/模型的图标、文字、合法字体选择和音频参数转成可校验资产，限定格式、尺寸、时长与资源预算，返回文件/哈希。不能将任意脚本执行作为默认资产工具。
4. **公开稳定下载。** SDK 与工具归档提供可校验下载/国内镜像、正确 Content-Type/长度/错误码；历史发行内容不变，失败不能以 200 HTML 冒充文件。
5. **独立复验。** 服务器选择匹配发行验证器，从实际包字节执行已有静态检查和新增产品门禁；报告分别呈现各证据层级和未测项。
6. **复用预览。** 先梳理现有网页模拟器是否真实执行最终 WASM、使用何种图形/音频宿主，再补差异和能力场景；网页听感与运行速度不标为目标设备通过。
7. **保留发布边界。** 生成/构建产物进入候选区；审核与正式上架分开。在线构建继续独立隔离、限时限额、无默认凭据和外网，不接触网站数据库或固件密钥。
8. **监测真实耗时。** 报告获取 SDK、工具准备、资产生成、模型生成、构建、验收各阶段耗时和缓存命中；用日志确认瓶颈，不许用“SDK 很大”代替诊断。

以上属于待实现或需复用验证的工作包；本次没有部署服务器，也没有执行收费模型质量/并发测试。

## 7. 主任务/生产运行时工作包

- 给出唯一当前按键映射、事件/状态语义、退出实现和首帧完成契约，纠正历史 API/按键说明。
- 梳理 UI 所有权、延迟提交、音频服务冷启动、系统按键音混入、资源仲裁、取消/退出的真实顺序，转成 SDK 可公开规则和对照样例。
- 当前系统可能混入按键音，并存在最长 500 ms 的等待路径；是否造成此应用卡音尚未证实。宿主应保证仲裁、时效、队列和生产者不被阻塞，不让 App 改系统音量绕过。
- 当前首屏屏障明确覆盖网络媒体，本地音频另有提前准备。跨音频家族统一屏障属于需要明确设计/验证的能力，不标为已有保证。
- 复用生产实现的首屏、资源配额、分配失败和清理回归，给出可公开的结果格式。
- 正确 App 仍触发宿主缺陷时，在主任务单独确定补丁范围；本方案不通过“关声音/关 TLS/扩权限/无限加缓存”规避。
- 真机记录固件/包哈希与场景，不能把历史版本的主机通过报告当当前硬件结论。

## 8. 发行和验收顺序

1. 本地完成规则草案、路由与链接检查；复核规则 ID、适用条件和引用，不能出现虚构 API/工具命令。
2. P0 完整模板和产品元数据检查先落地；P1 缓存/镜像紧随，缩短第一次及后续开发准备。
3. 复用设施实施 P2；统一客户端/服务器报告，未知层级如实标记。
4. 分配新 SDK 发行号，更新快照/文档、运行相关 SDK 自检，提交后冻结新发行。
5. GitHub/Gitee 使用同提交/标签；`release.py` 对 docs 目录有白名单支持，但新增文件仍必须进入 Git。新增根文件须先审查发行白名单。
6. 上传完整文件与哈希、校验新发行下载和核心文档可达后，最后更新最新索引；旧 2026.10.19.2 原样保留。
7. 用新环境完成一款含中文图标/原生动画/声音/退出的候选应用；分别记录主机与目标设备表现，验证外部 AI 确实读取了规则。

## 9. 持续收敛

每次新坑归档：最小复现 → 已确认层次与未知项 → 通用规则 ID → 可自动检查的工具/负例 → 当前发行与后续回归。
文档写规则，工具执行可证明部分，设备提供物理表现证据。美观、声音和流畅度保留用户及目标设备评价，不能由配置值自动宣布满足。

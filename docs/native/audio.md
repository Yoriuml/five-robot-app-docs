# 音频播放、录音与实时传音

专题 ID：`audio`。用到声音或麦克风时读取。Codec 为 ES8311，不是无源蜂鸣器，也不是可直接接 PCM 的 GPIO 喇叭。

## 接线和格式

I²C 7 位地址 **`0x18`**。`esp_codec_dev` 的 I²C 控制适配器使用左移形式时传 **`0x30`**；普通 7 位 I²C API 仍传 `0x18`，不要重复移位。MCLK10、BCLK8、WS12、DOUT6（播放）、DIN7（录音）、PA13（高有效）。

基线：I²S0 主机，标准 Philips 格式，16 bit，单声道，左槽，bit shift 开启，常用 MCLK＝256×采样率，基础采样率 24 kHz。使用 `driver/i2s_std.h` 的当前驱动；不与旧 I²S API 混用。C3 的具体模式见 [IDF I²S 文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c3/api-reference/peripherals/i2s.html)。

现有驱动入口接受 8～48 kHz，但不是这个区间的每个整数都保证 Codec 时钟系数支持。16 kHz 语音、24 kHz 基础播放等均要使用当前 Codec 表支持的 MCLK／采样率组合，并核对打开结果与实际时钟。原生固件不受 XApp 旧版 24 kHz 采样率合同约束，也不能照搬 XApp PCM direction 枚举。

有符号 PCM16 little-endian，发送端与接收端必须一致。网络封装、WAV 头、压缩数据都不能直接写入 PCM DMA。麦克风增益与输出音量分开；现有基线输入增益 30 dB、输出 70% 只是起点，不是所有音源的推荐响度。

## 启停与所有权

`关闭 → 申请必要 DMA／I²S → Codec 复位／配置 → 启动数字流 → 模拟输出稳定 → PA 开 → 工作 → PA 关 → 停止／释放`。

- PA 初始低。Codec 软件复位寄存器 0 写 `0x1F` 后要真实等待，现有实现为至少 10 ms 再加一个调度 tick，避免 100 Hz tick 下 5 ms 被取整成 0。
- 用 `esp_codec_dev` 时由它负责通道 enable／disable，应用不重复启停；Codec 的 `pa_pin=-1`，PA 由唯一管理者控制，避免库过早拉高。
- 输出建立后现有驱动预留约 150 ms 的 PA 唤醒／稳定路径；不能在这段期间已经把整段短音消耗掉，再开功放。停止或失败先关 PA，随后清理设备、接口、通道、DMA。
- 控制寄存器操作可持共享 I²C 锁；等待模拟稳定、PCM 写入和网络期间释放锁，否则 LCD 也会卡住。
- 只播放时只申请 TX；只录音时评估所选 Codec 适配层是否要求共享时钟／TX，但不要无理由建立完整播放链。双向录放需要协调同一 I²S 的格式、时钟和带宽。
- 不使用音频时不创建任务、Codec 和 DMA。部分初始化失败也沿逆序回收，重新进入可恢复。

现有输出基线为 6 个 DMA 描述符，每个 480 个单声道采样，16 bit 载荷约 5,760 B；双向时使用每方向 240 个采样的配置。描述符、驱动及 Codec 对象另占内存，这些数字不是总占用保证。DMA 时间窗口随采样率变化，要按样本数计算，不把 frames 与字节混淆。

## 避免音频互抢与卡顿

音频只有一个格式／设备所有者，按键音、提示音、音乐、录音通过仲裁器请求；可混音时做有界混音与饱和处理，不支持混音时显式暂停／恢复。不能按一次键就关闭正在工作的 Codec 或切采样率。

连续音频由专门的有界生产／消费任务供给，UI 只发命令。记录队列时长、欠载、丢帧、读写耗时和峰值；不能用提高音量掩盖格式、时钟或丢包问题。音效使用真实可辨识素材并处理音量归一，不用粗糙单频信号冒充木鱼／语音。

语音例：16 kHz×16 bit×1 声道＝32,000 B/s；20 ms＝320 samples＝640 B。网络发送、DMA、接收缓冲都用相同单位。录音连续读，不能“采一点 → 阻塞发送 → 再采一点”；发送拥堵时有界排队并统计丢帧，不覆盖尚在发送的帧。

传到电脑建议先做局域网 UDP／TCP，明确版本、序号、采样率、声道与长度。UDP 需要有界抖动缓冲、乱序处理、缺包策略；BLE 则按 MTU／连接间隔分片与背压，不能假定 BLE 是无限带宽串口。传输设计见 [network-storage](network-storage.md)。

## 验证顺序

先本地已知 PCM 短音 → 麦克风采集并统计非零／削波样本 → 电脑落 WAV 核对实际采样长度 → 网络双向／压力 → 与动画同时运行。分别记录数字路径通过和真人收听结果；离线解码快、WAV 可打开不代表实时通话、可懂度或声学验收已通过。AMBE 等编码器需要独立实现／许可／性能证据，不能因为有某个声明就承诺可用。

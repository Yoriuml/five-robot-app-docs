# AI 开发 XApp 的统一执行契约

> 适用：SDK 2026.10.20.2，API 2.15，包格式 1；历史发行保持不变。
> 本文是 AI 的唯一执行入口；SDK 工具、真实头文件与下列链接提供细节。
> 实施范围见[规则落地说明](ai-rules-rollout.md)，环境复用见[缓存说明](environment-cache.md)。人工规则与自动检查的证据范围分别记录。

## 1. 使用方式与权威来源

用户只需提供一句话：

```text
按官方索引对应 SDK 的 docs/ai-workflow.md 开发 XApp：【我的功能、界面和交互需求】。
```

资料入口：[官方版本索引](https://site.flashbot5.com/developer/v1/index.json)。
本发行先部署至[测试站索引](https://site.flashbot5.cn/developer/v1/index.json)；正式站可能仍指向旧发行。开始时选定一个索引及发行后固定使用，不在中途跟随另一个站点的 latest。
备用：[GitHub](https://github.com/Yoriuml/five-robot-app-docs)、[Gitee](https://gitee.com/yorium/five-robot-app-docs)。

- **BASE-01 授权范围。** 用户需求和明确限制优先。开发目标是独立 `.xapp`，不因完整仓库权限而修改设备固件、公共 API、驱动、分区、参考工程或其他应用。发现平台缺口，完成不受影响的工作并提出具体接口/运行时需求；不私自实现设备补丁。
- **BASE-02 固定发行。** 从索引选定一个 SDK 发行版。SDK 发行号、API 版本、应用版本、包格式及设备固件版本分别记录；API 都叫 2.15 不代表不同 SDK 工具可以混用。GitHub/Gitee 使用索引指定的同一标签与提交。
- **BASE-03 单一事实来源。** 本文约束执行流程；`sdk-release.json` / `SDK-SNAPSHOT.json` 定义发行与来源，`api.json` 导航符号/最低版本/权限，真实[SDK 头文件](../sdk/xapp/x622_xapp.h)定义 ABI 与结构。行为、单位、返回值、所有权和配额还需匹配同发行已确认的目标配置与勘误。数值预算统一查[内存配置](memory-profile.md)。已证实过时的注释应由 SDK 维护方明确修订，不能让外部 AI 自行猜测；历史项目说明和旧示例不得覆盖当前契约。
- **BASE-04 不补造 SDK。** 不能从能力名称推导接口，也不能从网上片段拼接结构、重写猜测头文件。真实声明仍不可得时，只阻塞依赖该声明的功能，准确说明缺失文件；其他可独立完成的工作继续。
- **BASE-05 能力与证据。** 先在内部记录页面/状态、按键、退出路径、所需服务、最低 API、最小权限、最重并发组合和验收方法，再开始实现。只向用户报告关键结论与阻塞，不逐步索取例行确认。

完整阅读本文；涉及某能力时，实施前打开对应头文件与本文链接，不为未使用的功能增加依赖、权限或测试负担。

## 2. 环境准备、下载与时间

- **ENV-01 先查再装。** 先运行 `python tools/doctor.py`，可带 `--app` 检查资产缓存。按[工具定位顺序](troubleshooting.md)复用已验证的 Zig/WABT；不要每个应用重新下载整套工具。支持显式路径、环境变量、PATH、SDK `.tools` 和[共享缓存](environment-cache.md)。源码/JSON 按 UTF-8 读写，显式指定编码，不依赖系统区域设置；自检覆盖英文 Windows。
- **ENV-02 一次获取。** 下载完整 `sdk.zip`，按索引核对字节数与 SHA-256；解压后在本地校验文件清单。禁止对完整 SDK 中已有文件逐个联网获取。模板与头文件必须同发行；已有完整 SDK 不必再下模板 ZIP。
- **ENV-03 缓存按内容认定。** 已通过版本与哈希验证的归档/工具可复用；损坏、版本错误的缓存不能当成功。准备阶段区分索引、SDK、工具链、依赖、解压各自耗时。共享缓存与自动镜像切换是[待实现工具项](ai-rules-rollout.md)，当前不得假设已存在新参数。
- **ENV-04 有界网络尝试。** 记录具体 URL、HTTP 状态、字节数或超时阶段。同一失败方式不盲目重复；换固定发行镜像、ZIP、PowerShell Invoke-WebRequest 等可用方式。对中断的大归档保留诊断，不能下载 HTML 后当 ZIP 使用，也不能修改预期哈希放行。
- **ENV-05 只补缺项。** 缺锁定版本工具时才使用 `tools/bootstrap.py`；已有归档用 `--archive-dir`。解压后检查真实可执行文件与版本。Python 指向商店、系统平台/架构不符、可执行权限缺失分别处理；不能仅凭文件名判断可运行。不要因缺少可选图标/字体工具重装全部工具链。
- **ENV-06 不让准备吞掉开发。** 网络等待期间可独立设计状态机、源码和资源清单。连续下载失败后给出准确阻塞与已完成源码，不无限探索下载方式。不得省略最终校验，或将旧包冒充本次产物；环境正常时持续完成已授权任务。
- **ENV-07 可移植。** 不依赖作者工作站的绝对路径；源文件使用明确编码。多行命令、JSON、资源路径与参数正确引用。临时文件和缓存放约定目录，不自动清空用户目录；不把工具二进制、凭据和个人环境提交到 SDK。

基础创建与构建命令见[快速开始](quickstart.md)；锁定版本以本发行 `toolchain.lock.json` 为准。

## 3. 模板、应用名称与图标

- **APP-01 基于模板。** 用 `tools/create_app.py` 从最接近的已验证模板创建，不重建头文件、构建链或包格式。模板是基础，不是完整产品验收证明。
- **APP-02 稳定身份。** 应用 ID、应用版本与用户名称分别处理。更新保留同一 ID、递增应用版本；修改名称不能顺便变更 ID。保留可显示的英文 `name` 回退；不能假设任意 UTF-8 包名能被旧系统字体绘制。
- **APP-03 发布展示必需。** 面向用户交付的应用应有 `launcher.names.en`、`launcher.names.zh`、`launcher.icon` 和中文所需 `launcher.font`。这些在包格式中仍是可选字段，属于产品交付要求；旧包兼容性不能被误改为包格式非法。
- **APP-04 正确生成元数据。** 图标、字体路径相对 `app.json`。方形 PNG 由官方打包器转换为设备使用的 32×32 RGB565+A8；中文名由已获授权且覆盖字形的字体生成原生尺寸子集。不要直接把 PNG、TTF 放进资源目录就宣称系统会显示。
- **APP-05 最终包反查。** 打包后运行 inspect，核对 `launcher.names`、图标存在标记、字形覆盖、资源数量及大小；不能以源目录中的图片或截图代替。保留资源 `__xapp__/launcher.bin` 只由官方工具生成。
- **APP-06 资产可重建。** 随源码交付资源生成方法、必要输入与来源/许可证，不夹带未授权产品资源或私有字体。生成二进制资产需要合法生成工具；平台仅支持文本资源时，说明缺少哪种资产通道，不上传伪 PNG 或无法重现的占位数据。

清单与字节限制见[manifest](manifest.md)及[展示元数据实现](../tools/xapp/presentation.py)。中文按 UTF-8 字节上限验证，不能把字节数当汉字数。

## 4. ABI、内存模型与构建

- **ABI-01 运行模型。** XApp 是 freestanding C/C++ → wasm32，不是 ESP-IDF 程序，不运行 Python/JS。不能链接 LVGL、FreeRTOS、WASI、GPIO/SPI/I2S 对象、私有固件指针、桌面线程/异常/标准库或 malloc/free。
- **ABI-02 真实结构。** 使用本发行真实结构和函数签名；正确填 size/version、保留零字段、枚举、字节序、对齐、路径长度和输入长度。传入字节数使用真实 sizeof，不能凭网上示例猜测。
- **ABI-03 固定内存。** 遵守[固定内存配置](memory-profile.md)，区分逻辑 64 KiB 页、实际物理申请、静态区、C 栈和解释器栈。不使用 memory.grow/size，不把页尾 padding、资源区或 `__heap_base` 之后空间当作可用堆。
- **ABI-04 最终链接。** 必须保留 init/tick；使用事件、清理或分步启动时，按契约实现并保留相应导出。`required_exports` 和 `required_imports` 只列实际需要的符号；不强制无用 random，也不把缺失函数的空壳当完成功能。
- **ABI-05 权限与版本。** 声明覆盖实际导入的最低 API 与最小权限。当前头文件版本不自动等于应用声明；增加权限不能修复错误参数、内存不足或服务冲突。
- **ABI-06 保留构建证据。** 最终包包含的 WASM 才是验收对象。记录其 imports/exports、WASM 大小、内存边界、工具版本和哈希，不能仅查看未链接源码。

## 5. 生命周期、首屏与调度

- **RUN-01 回调有界。** init/tick/event/shutdown 及时返回。禁止 while 等按键、网络完成、播放结束或资源空闲。异步服务用状态机、时间与后续回调推进；输入轮询次数不能成为工作量失控的循环。
- **RUN-02 时间来源。** 按 API 的时间单位与位宽处理 delta、边界和计数回绕，不以 tick 次数假装经过时间。millis/运行时长不是当前日期时间；无时钟接口时不得编造获取系统时间的函数。
- **RUN-03 完整首屏。** 先保证离线可达的完整有效首屏、输入与退出，再叠加网络、音频和复杂效果。网络准备、音频冷启动不能让应用看起来永远黑屏。分步绘制遵守 SDK 的首帧完成约定，不以多等几个 tick 掩盖未完成状态。
- **RUN-04 启动完成语义。** 如果使用 `xapp_startup_ready`，必须读当前主头文件的约定、完整页面或完整加载页合成后才报告完成，查询无副作用，并保留最终导出；不能仅因提交背景成功就无条件返回 ready，也不能永久阻塞完成。宿主延迟原生场景提交的时序不是由调用次数推断，不能关闭背光遮掩不完整首屏。
- **RUN-05 状态与目标。** 按键、数据、动画、网络和播放分别建模，状态切换先取消旧请求或标记其结果失效。迟到结果、退出后结果、重复事件不得操作已释放界面或新一轮会话。
- **RUN-06 正确失败。** 每个接口按自己的成功值、长度和错误语义判断；不能统一认定只有 0 才成功，也不能无视负数。先验证结果，再读取输出；禁止把负长度转成无符号数。

## 6. 按键与退出

- **KEY-01 明确映射。** 区分 UP/DOWN/CONFIRM/AUX 逻辑键、硬件 K 编号及物理方向。先核对目标设备与用户约定，再确定中键动作、左右/返回等行为；不能从 BACK 旧别名推导系统会自动退出。
- **KEY-02 启动松手。** 屏蔽启动应用时尚未释放的按键；启动松手后接受新动作。短按、长按、重复/按住分别处理，同一次操作不能同时执行短按与长按动作。
- **KEY-03 状态与边沿。** input_state 用于持续状态，事件或边沿用于一次性动作。按下与释放匹配；需要“按下发声、松开停声”等行为时，不等长短按判定后才行动。
- **KEY-04 退出可达。** 每个页面及失败状态保留明确、用户可理解的退出/返回路径；需要退出时调用 `x622_exit` 后立即返回，不再绘图或启动服务。不要把示例的长按 2 秒强加给所有应用，也不能依赖不存在的系统退出捷径。
- **KEY-05 连续操作。** 覆盖按住启动、快速连按、换模式、长按边界、释放丢失、重复进入和退出。切换动画期间的输入策略明确，不能让等待动画成为永久锁键。
- **KEY-06 手势隔离。** 当前生产宿主转发 TRIGGER 事件，不得假设始终收到完整 down/up 事件流。到达长按阈值立即执行需状态轮询与单调时间；消费后锁定至松手，防止一次手势跨页面连续触发。event 的 pressed_mask 是物理键位序，不能直接当 input_state 位图。

2026-10-20 生产源码只读评审确认下表；发布方还须将其绑定目标固件/配置，不能据此声称所有已发布固件均已实测：

| 产品角色 | input_state 位 | 历史 ABI 事件名称 |
| --- | --- | --- |
| 上键 K4 | 1 | X622_INPUT_UP |
| 下键 K3 | 2 | X622_INPUT_DOWN |
| 左键 K1 / 返回 | 4 | X622_INPUT_CONFIRM |
| 中键 K2 / 确认 | 8 | X622_INPUT_BACK / AUX |

因此不能把 `X622_INPUT_CONFIRM` 的名字直接解释为本产品中键。本发行模板的 product_input.h 保留历史 ABI 值并适配实际角色。应急关机在已确认生产配置为 6 秒，公共头文件的“20 seconds”注释已知过时；本次不改公共头文件，该时长也不作为普通 App 退出策略。

## 7. 图形、中文与视觉质量

- **GFX-01 选择绘图路径。** 原生 UI 取得显示权时，不同时提交冲突的 gfx_submit/resource/blit；切换路径前按契约释放。BUSY 是所有权或时序信号，不能忽略后宣称绘制成功。
- **GFX-02 纹理与节点。** 优先使用适合该效果的缓存 UI；稳定节点 ID、有序场景、正确裁剪。资源/字体离线生成，纹理尽量只上传一次；不每帧读包、解析字体、重新配置 UI 或重传相同场景。
- **GFX-03 非线性动画。** 动画以时间推进且可结束；目标未变化时不反复重启动画。使用公开插值能力或有界分段目标，不编造 easing、透视或旋转字段；复杂效果必须测量实际动态区域、计算量与传输成本。
- **GFX-04 合成完整脏区。** 移动元素覆盖旧位置与新位置，脏区包含正确背景、遮挡与文字。避免全屏逐像素计算、层层透明覆盖、每帧全屏刷新和无变化刷新；不能通过粗糙降色、吞掉关键动画或减少主信息来假装优化成功。
- **GFX-05 配额先计算。** 覆盖最坏分支的节点/命令数、单纹理大小、槽位、缓存、裁剪工作量及动画包络。禁止静默丢命令；数组容量不能只按默认页面估算。
- **GFX-06 中文与数字。** 传统 TEXT 不是中文字体接口。正文中文、列表名称字形、图标是不同资源，分别验证。文字在原生显示尺寸合成，避免放大低分辨率字形；不能假定系统字体指针对 App 开放。
- **GFX-07 视觉约束。** 优先清晰主体、可读数字、合理对比与有目的的色彩。用户要简洁或少字时，不添加小字说明、调试信息墙和多余标签；鲜艳不等于全屏 RGB 彩虹，流畅也不等于只有淡入淡出。所用风格与参考元素遵守用户需求。
- **GFX-08 性能证据。** frame_ms 是目标间隔，不是实际 FPS。看渲染耗时、present 耗时、像素数、deadline misses、纹理上传和设备现象；区分菜单与最重运行画面。电脑预览流畅不能证明 C3 达标，原生 API 也不自动保证负载合适。
- **GFX-09 可见首屏。** 结构合法不等于可见：显式设置透明度、裁剪窗口、节点/纹理尺寸与位置。opacity=0、全部裁到屏外、前景背景同色都可能返回成功。验证主内容真正出现在完整首帧中，不能由参数桩或纯背景占位宣布通过。

声明与限制见 [x622_ui.h](../sdk/xapp/x622_ui.h)、[光栅接口](../sdk/xapp/x622_raster.h)和[扩展导航](api-extensions.md)。

## 8. 内存、资源与并发预算

- **MEM-01 全部计账。** 分别计算保留的 WASM 源镜像、物理线性内存与静态区/C 栈、解释器栈、宿主纹理缓存、首屏缓存、DMA/条带、音频/解码器、网络/TLS、请求与解析缓冲。16 MiB Flash 不是可用 RAM，WASM 静态内存低于上限也不能证明设备堆够用。
- **MEM-02 分阶段峰值。** 覆盖启动首屏、服务冷启动、最重音画网络组合、模式切换新旧资源重叠、退出清理。还要考虑所需最大连续块与 DMA 能力；有总空闲堆不等于能分配目标块。缓存、条带等接口上限不是默认最优配置，各项配额不能同时拉满。
- **MEM-03 有界读取。** 图像/字体/音频/大表存包资源，使用条带、分块或流；读前验证 resource_size 与偏移/实际返回长度。禁止全屏 RGB565 数组、大局部数组、深递归、运行时生成巨大查找表。
- **MEM-04 降级与恢复。** 资源不足时减少可选缓存/同时服务或延迟非关键工作，保留主信息和退出。不得改系统限制、强抢音频、无限重试或循环重启；合理预算仍失败时报告具体平台证据。
- **MEM-05 包内路径。** 核对路径大小写、包内相对路径、斜杠、偏移对齐、格式和资源边界；不能把开发机路径或服务器文件路径当成设备资源路径。
- **MEM-06 回归度量。** 优化前后使用同一场景和实际负载，记录效果、内存与耗时；新版本号、较小 WASM 或更少代码行都不是“更流畅”的证明。

## 9. 音频与系统声音共存

- **AUD-01 选定播放体系。** 按当前能力选择 resource、双轨、stream、tracker 或 media 的适用路径；遵守其互斥关系，不在彼此活跃时混用，不用一种接口修补另一种接口的状态。
- **AUD-02 格式与单位。** 核对采样率、声道、位宽、字节序、帧长、偶数偏移、PCM/Opus/模块音乐的实际编码；文件扩展名不是格式证明。单位是 bytes 还是 samples 逐接口核对。
- **AUD-03 声部与优先级。** 背景/效果按对应声部、增益、duck 和优先级管理；停止某一效果优先使用该声部的 STOP。全局 audio_stop 不应在每次按键或每帧执行。
- **AUD-04 请求与异步错误。** 播放接受不代表已经出声；按接口读取 status/native_error。BUSY、队列满或部分接受依约在后续 tick 处理，禁止忙等。完成位置或已提交样本数不能冒充实际可听时钟。
- **AUD-05 不重复冷启动。** 保持播放状态；循环音轨不每个 tick 重启，按住发声不反复开关 codec/播放任务。连续音效按设计节奏触发，避免将长音尾不断截断。
- **AUD-06 共存边界。** 系统按键音可能继续混入 App 输出。App 不私自关闭全局按键音、直接操作 I2S 或抢设备租约；验证快速操作与音画共存。遵守公开接口仍有抢占/断音时，保留时序和平台日志，交由运行时负责方处理。
- **AUD-07 退出与切换。** 切换来源或退出时按 API 取消旧请求、停止对应播放并释放拥有的服务；不能依赖下一次进入 App 自动冲掉旧声音。
- **AUD-08 启动屏障。** 当前生产宿主明确延迟的是网络媒体，本地音频另有提前准备路径。模板应在完整首屏后触发业务音频；不得宣称所有音频家族已受统一首帧屏障保护，也不能凭一次静态检查证明启动无争用。

对应声明：[双轨](../sdk/xapp/x622_audio.h)、[音频流](../sdk/xapp/x622_audio_stream.h)、[信号](../sdk/xapp/x622_signal.h)、[Tracker](../sdk/xapp/x622_tracker.h)及主头文件。

## 10. 联网、外部数据与时间

- **NET-01 离线启动。** UI、退出和必要缓存不依赖联网成功。异步联网，显示明确但简洁的等待/错误状态，禁止在 init 内同步等 Wi-Fi/HTTP；断网、空数据和服务不可用仍可进入应用。
- **NET-02 有界请求。** 超时、取消、重试/退避、最大响应体和最大解析深度明确。读取返回值先验证，再解析；处理分段、部分读、空响应、非预期状态、截断和未知字段。
- **NET-03 正确归因。** 分清 Wi-Fi、DNS、TLS、HTTP、协议解析、数据过期和 UI 更新失败。保留首个具体 native_error/transport/status 与阶段，不从一个笼统失败日志推断根因。
- **NET-04 保留可信验证。** HTTPS 验签失败结合证书链、时间、算法、系统堆/连续块及运行时诊断判断。不能为联网成功改 HTTP、关闭证书/签名检查、删除根证书验证或无限重试；不要将所有失败都叫证书不匹配。
- **NET-05 数据与缓存。** 使用真实公开接口和明确数据版本；不把示例数据冒充实时数据。缺字段、空列表、赛季/日期边界、时区、分页、限流和过期缓存有可恢复行为。联网成功后只更新变化的信息。
- **NET-06 资源竞争。** Wi-Fi/TLS 与音频/显示同时运行按实际组合测量；同一 App 离线正常、联网失败时优先调查并发预算和错误时序，不先扩大权限或修改业务数据。
- **NET-07 凭据与端点。** 凭据在用户可配置的私有数据中按公开能力处理，不能硬编码到源码、报告、包或日志。不假定 PC 预览的网络、证书和速度等同于设备。

对应声明：[HTTP](../sdk/xapp/x622_http.h)、[扩展 HTTP](../sdk/xapp/x622_http_ex.h)、[网关](../sdk/xapp/x622_gateway.h)。

## 11. BLE、数据报、流与信号处理

- **IO-01 能力边界。** 先核对 BLE 外设、HID、GATT、ESP-NOW 或网关角色；存在 BLE API 不代表能扫描、作 Central 或任意构造广播。需求超出公开声明时提出通用能力缺口，不链接私有服务。
- **IO-02 报告与消息。** 按真实结构、报告 ID、长度、字节序与队列上限处理；读取条数/字节数先检查。处理断开、丢包、重复消息、队列溢出与发送中的 BUSY，不假定发送排队等于对端已收到。
- **IO-03 交互完整。** HID 等按下/触摸状态要有对应释放；退出、异常和重新连接不能留下按住状态。平台要求的手机辅助功能和配对前提写在安装说明，不能当作协议自动具备的能力。
- **IO-04 有界计算。** PCM、信号、VAD、Tracker 与音频流遵守输入对齐、窗口、块长、状态和重置契约。信号计算分块推进，不在输入回调中执行无限分析或大规模浮点/三角函数计算。
- **IO-05 资源生命周期。** 网络/无线角色切换按公开接口释放旧会话，拒绝迟到结果；设备服务不能由 App 自建线程或绕过管理器直接抢占。

按实际使用阅读 [BLE](../sdk/xapp/x622_ble.h)、[GATT](../sdk/xapp/x622_ble_gatt.h)、[数据报](../sdk/xapp/x622_datagram.h)、[加密](../sdk/xapp/x622_crypto.h)和[扩展导航](api-extensions.md)。

## 12. 私有存储、失败与清理

- **STATE-01 私有数据。** 配置存应用私有空间；包资源只读，不写回资源区。存储格式有长度、版本和合理缺省值，处理首次运行、损坏、截断与空间不足。
- **STATE-02 限制写入。** 设置变化时有界保存，不每帧写 Flash；大文件用可用文件流接口并正确关闭。使用私有文件接口的 staging/commit/abort 时遵守其成功与取消语义；其他接口不得套用未经提供的事务能力，不编造 rename/文件系统接口。
- **STATE-03 升级数据。** 同 ID 更新、卸载和重装可能影响私有数据；查当前安装契约后描述行为，不能无依据承诺保留全部用户数据。
- **STATE-04 清理顺序。** 先停止接受新工作，取消请求/播放并使迟到结果失效，再释放场景/纹理/句柄。shutdown 有界、可重复调用，不因为部分初始化失败而跳过已取得资源的释放；不能依赖 shutdown 必定被执行才保存关键数据。
- **STATE-05 可诊断。** 错误状态不进入空屏/永久等待；能显示时给最少且可理解的反馈，始终保留退出。诊断记录首个失败调用、参数大小、阶段、返回值和资源组合，不在每帧打印或泄露凭据。

## 13. 验收层级与最坏情况

- **TEST-01 分层报告。** 分开记录静态包/ABI/WABT 校验、C 主机桩、实际 WASM/兼容宿主执行、目标设备验收。每项为 passed/failed/not_run/blocked/not_applicable，并附版本/包哈希/证据；不能手工把未测标志改为 true。
- **TEST-02 不替换被测实现。** 用最终包中的 WASM/资源做运行验证。重新编写的 C/Python 预览或 HTML 模型只能说明模型表现；桩返回成功、调用次数正确，不证明真实 ui_scene/纹理解码/首屏合成/音频调度成功。
- **TEST-03 当前能力真实。** 当前 SDK 不包含私有设备服务模拟器。缺真实运行条件时如实交付静态结果和未测项，不为得到 passed 伪造 runtime/hardware 工具。后续新增宿主也必须说明与设备的差异。
- **TEST-04 功能路径。** 覆盖启动键松手、每种操作/模式、快速连按、长短按边界、退出、再次进入、数据读写和异步取消。错误后仍能退出，退出后无活动声音或迟到界面更新。
- **TEST-05 最坏资源。** 遍历最大文本/图元/节点/纹理、最重并发服务、资源缺失/损坏、分配不足、超时/断网/空数据。构造真实边界，不写只镜像实现的“自证”测试；故障不能被悄悄吞掉。
- **TEST-06 目标设备指标。** 记录固件版本、API/SDK、安装包哈希、运行时长、启动首屏、连按、音画网络同时运行及资源释放。设备帧率、听感、SPI 吞吐、系统按键音共存、峰值堆等需目标设备证据，不由配置值或 PC 速度宣称达标。
- **TEST-07 有限且相关。** 先完成必要校验；通过后只有新变更、失败或未决风险才扩大/重复测试。性能回归对比同一场景，不能只测试菜单或静态页面；不为凑测试数量拖延交付。

## 14. 打包、安装与交付

按实际目录运行工具，从最终包独立验证：

```sh
python tools/doctor.py
python tools/create_app.py --template native-ui --id my-app --name "My App" --output dist/my-app
python tools/build.py --app dist/my-app -o dist/my-app.xapp
python tools/validate.py dist/my-app.xapp --product
python tools/check_product.py dist/my-app.xapp --report dist/my-app.product.json
python tools/xapp/xapp_tool.py inspect dist/my-app.xapp
```

- **SHIP-01 最终包检查。** 核对来源、ID、版本、最低 API、权限、导入导出、资源/launcher、内存及 SHA-256；下载到设备的包应与交付哈希一致。构建失败不能把旧输出当成功，不能只改扩展名、包头版本或报告字段冒充修复。
- **SHIP-02 安装边界。** 交付 `.xapp` 与明确安装说明。用户授权前不自动连接串口、安装、擦除、烧录或改设备串口速度；安装模式/端口占用/权限/主机与设备波特率分别确认，单改电脑选项不等于设备协议已同步。
- **SHIP-03 固件媒体是独立任务。** 只有明确要求才制作整机工厂包；确认分区/恢复布局、实际已构建固件和应用版本、语言/主题、总 Flash 容量与写入范围。完整镜像即使不调用整片 erase 仍可能覆盖数据；不能将其称为保留数据的 App 更新。
- **SHIP-04 可审查交付。** 交付源码、清单、资源/生成方式、真实 `.xapp`、报告、SHA-256、按键与安装说明。简要标明已测/未测、实际版本、重要限制与环境耗时；避免长篇重复的“全部通过”叙述。
- **SHIP-05 发布独立复验。** 客户端 validation.json 仅作线索；服务器从包字节独立复验。静态通过可成为候选，不等于真机通过，也不自动上架。SDK 与服务器的规则、工具、报告必须同发行可追溯。
- **SHIP-06 新坑入库。** 新问题记录最小复现、App/SDK/运行时/服务器层次、根因证据与未知项、受影响发行、修复和回归用例。扩充本契约中稳定规则 ID；能自动检查的进入对应工具，不能把某一个 App 的偶然修复变成所有 App 的强制规则。

## 15. 结束条件与平台缺陷

- 功能、资产和必要校验完成后直接交付；缺真实设备不构成伪造通过的理由，也不妨碍交付已验证的候选包。
- API 不支持、平台错误、工具链不可达和应用实现缺陷分别报告。保留准确证据，不以关闭 TLS、改权限、扩大缓冲、关系统声音或修改私有固件绕过。
- 对用户明确要求的设备/API 改动，另列具体范围交由相应任务处理；本文不会自行授予这些权限。

详细工具建设、模板和服务器工作见[规则落地方案](ai-rules-rollout.md)；现有发行约束见[发行规范](releases.md)。
